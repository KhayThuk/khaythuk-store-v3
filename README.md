# Khay Thuk

ร้านค้ารหัสดิจิทัลภาษาไทย มีแค็ตตาล็อกตั้งต้น 30 รายการใน 12 หมวดจากหน้า [หมวดหมู่ Nadear Store](https://nadearstore.rdcw.xyz/categories) พร้อมภาพปกที่ทำให้ Khay Thuk โดยเฉพาะ ราคาเป็นค่าเริ่มต้นที่แก้ได้ รายการที่อ้างอิงช่วงราคาใช้ค่าต่ำสุด และเริ่มด้วยสต็อกศูนย์

## เริ่มใช้งานบน Sites

1. เปิด URL ของ Site ด้วยบัญชี ChatGPT เจ้าของ Site ขณะที่ตั้งเป็นส่วนตัวสำหรับเจ้าของ
2. กด **ตั้งค่าร้าน** แล้วเลือก **สร้างบัญชีแอดมิน** ระบบสร้างชื่อผู้ใช้ `admin` กับรหัสผ่านสุ่ม 32 ตัวอักษรเมื่อกดปุ่ม หน้าจอแสดงรหัสผ่านครั้งเดียว เก็บในตัวจัดการรหัสผ่าน
3. เปิด **หลังร้าน → สินค้า → แก้ไข** เพื่อแก้ชื่อ รูป และราคา ในส่วน **รหัสสินค้าหลังสั่งซื้อ** วางรหัสหนึ่งบรรทัดต่อหนึ่งชิ้นแล้วกด **เพิ่มรหัสเข้าสต็อก** สต็อกคำนวณจากรหัสที่ยังไม่ได้ส่ง ระบบส่งรหัสตามลำดับที่เพิ่มหลังตัดเงินและแสดงให้ผู้ซื้อเห็นใน **คำสั่งซื้อ** หากมีรหัสซ้ำ ระบบจะไม่เพิ่มทั้งชุด
4. ตั้งข้อมูลบัญชีรับเงินจริงใน **บัญชีรับเงิน** ระบบเปิดรับอัปโหลดสลิปเมื่อกรอกข้อมูลครบ
5. เปิด **ตรวจสลิป** เพื่อตรวจรูปและบันทึกจำนวนเงินกับเลขอ้างอิงจากธนาคาร เมื่ออนุมัติระบบเพิ่มยอดให้ผู้ส่ง การใช้เลขอ้างอิงเดิมจะถูกปฏิเสธ
6. หน้า **สมาชิก** ใช้เพิ่มหรือลดยอดพร้อมเหตุผล หน้า **ประวัติยอดเงิน** แสดงยอดหลังทำรายการและผู้ดำเนินการ

การสร้างบัญชีเจ้าของใช้ตัวตนจาก Sites และตั้งค่า `ADMIN_INITIALIZE_FROM_OWNER=1` เฉพาะช่วงที่ Site เป็น owner-only ปิดค่านี้และ deploy ใหม่ก่อนเปิดสิทธิ์ให้ลูกค้า ฐานข้อมูลจำกัดแอดมินไว้หนึ่งบัญชี

## รันบนเครื่องสำหรับพัฒนา

ต้องมี Node.js 24 ขึ้นไป จัดการฐาน SQLite และรูปใน `.local/` โดยอัตโนมัติ

```sh
npm test
npm run dev
```

เปิด http://127.0.0.1:4173 เพื่อทดลองจากเครื่องที่รันคำสั่ง โหมดพัฒนาเปิดการตั้งค่าแอดมินสำหรับการทดสอบภายใน เรียก `npm run build` เพื่อสร้าง Worker ที่ `dist/server/index.js` โฮสต์กำหนด binding ชื่อ `DB` และ `BUCKET` จาก `.openai/hosting.json` และใช้ SQL migration ใน `drizzle/`

## ตรวจสลิปโดยอัตโนมัติ

ไฟล์ `src/worker.mjs` มีสัญญาการเรียกตัวเชื่อมต่อกลาง รอระบุผู้ให้บริการจริงเพื่อเขียนตัวแปลงให้ตรงกับเอกสารและทดสอบกับบัญชีรับเงิน เมื่อเชื่อมแล้ว เว็บจะทำงานต่อได้เองขณะอัปโหลดสลิปโดยเรียกผู้ตรวจสอบจากเซิร์ฟเวอร์ผ่าน HTTPS

- `SLIP_VERIFY_URL` เป็น URL สำหรับ POST multipart ฟิลด์ `image` ปลายทางต้องได้รับอนุญาตให้ประมวลผลสลิปลูกค้า
- `SLIP_VERIFY_KEY` ใช้เป็น Bearer token ฝั่งเซิร์ฟเวอร์ เก็บใน Sites runtime secret
- `SLIP_RECEIVER_ID` คือรหัสผู้รับที่คาดหมายจากผลตรวจ ซึ่งต้องสอดคล้องกับบัญชีที่แสดงในหน้าร้าน
- ผลจากตัวเชื่อมต่อต้องเป็น JSON ที่มี `verified` แบบ boolean, `currency` เป็น THB, `receiverId`, `reference` จากธนาคาร, `amountSatang` เป็นจำนวนเต็ม และ `transferredAt` เป็นวันเวลาการโอน
- ระบบยืนยันชื่อผู้รับจากรหัสบัญชี ตรวจสกุลเงิน อายุรายการ และเลขอ้างอิงซ้ำ ก่อนทำรายการเข้ากระเป๋า สลิปที่ตรวจอัตโนมัติไม่ได้จะรอตรวจในหลังร้าน

ทดสอบตัวเชื่อมต่อด้วยผลจำลองแล้ว ก่อนรับเงินจริงให้ตรวจสลิปโอนสำเร็จ สลิปเดิมอัปโหลดซ้ำ ผู้รับผิด ยอดผิดปกติ และกรณีผู้ให้บริการตอบช้าในระบบจริง

## ซอร์สและข้อมูล

- `public/` มีหน้าร้านภาษาไทย สไตล์ ภาพที่สร้างสำหรับโปรเจกต์นี้ และโค้ดส่วนติดต่อ
- `src/worker.mjs` มี API สำหรับสมาชิก เซสชัน สินค้า คำสั่งซื้อ ยอดเงิน และสลิป
- `drizzle/` มีโครงสร้างฐานข้อมูลและกลไกจัดสรรรหัส ปรับสต็อก และตัดยอดในคำสั่งฐานข้อมูลเดียวกัน ใช้หน่วยสตางค์
- `scripts/` มีตัวสร้าง Worker สภาพแวดล้อมทดลอง และการทดสอบ
- เว็บโฮสต์เก็บข้อมูลสมาชิกและรายการใน D1 เก็บรูปสินค้าและสลิปใน R2 สลิปเปิดผ่าน API ที่ตรวจบทบาทแอดมิน
- ZIP ใน Drive เป็นสำเนาซอร์สและคู่มือ มีไฟล์ตัวอย่างสำหรับค่าตั้งต้น ข้อมูลลูกค้า สลิป เซสชัน และคีย์ระบบอยู่ในระบบที่ดำเนินงานแยกจาก ZIP
